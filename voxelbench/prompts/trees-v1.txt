Task:
Implement the tree growth method of the SIGGRAPH 2009 paper "Self-organizing tree models for image synthesis" (Palubicki, Horel, Longay, Runions, Lane, Mech, Prusinkiewicz; https://www.algorithmicbotany.org/papers/selforg.sig2009.html, the PDF is linked from that page) as a 3D browser demo in which a tree grows in front of the viewer, one season at a time. Follow the paper's method; the numbers below are sensible starting values that you may tune. It must include:
1. Metamers and buds. The tree is a hierarchy of metamers (an internode with a leaf and a lateral bud). The trunk starts as a seedling of 2 metamers pointing up. Every axis ends in a terminal bud and every metamer carries one lateral bud. Growth is rhythmic: each season, every bud may produce a new shoot (a row of new metamers), and buds created in a season cannot grow before the next one.
2. Light from shadow propagation on a voxel grid. Cell edge about one internode (128 x 160 x 128 cells, seed at the bottom centre). Each season clear the grid; every bud in voxel (I,J,K) adds shadow to the pyramid below it: voxel (I+i, J-q, K+k) with |i| <= q, |k| <= q, q = 0..qmax gets the increment a*b^(-q) (start with a = 0.3, b = 1.5, qmax = 5). A bud's light is Q = max(C - s + a, 0), s being the shadow in its voxel and C = 1 full exposure. A bud's optimal growth direction V points to the neighbouring voxel with the lowest shadow value inside its perception cone (for example 5x5x5 voxels, within 60 degrees of the bud direction).
3. Resource allocation, extended Borchert-Honda model, two passes per season. Basipetal: each internode stores the summed light of the buds above it, split into Qm (through the main axis) and Ql (through the lateral branch or bud). Acropetal: the base gets v_base = alpha * Q_base (alpha about 3; if the seedling never grows, alpha is too small), and at every branching point the resource v splits into v_m = v * lambda*Qm / (lambda*Qm + (1-lambda)*Ql) for the main axis and v_l = v * (1-lambda)*Ql / (lambda*Qm + (1-lambda)*Ql) for the lateral. lambda is the apical control: above 0.5 favours the main axis (tall, narrow, excurrent crown), below 0.5 favours the laterals (wide, decurrent crown). Default lambda = 0.5; the paper shows 0.46 to 0.54.
4. Shoot growth. A bud receiving v grows n = min(floor(v), 6) new metamers this season, each of length v/floor(v) internode units (floor(v) = 0: the bud stays dormant and may grow in a later season). Terminal buds continue their axis, lateral buds start a new axis. The direction of each new metamer is the normalised weighted sum of its default direction, V (weight about 0.25), a tropism vector (up, weight about 0.15) and a small seeded random perturbation (about 0.1). Lateral buds sit at a branching angle of about 45 degrees with phyllotaxis: spiral (azimuth +137.5 degrees per metamer) or alternate (180 degrees), selectable.
5. Shedding. After the basipetal pass, compare the total light collected by each lateral branch with its size in internodes; below a threshold (start at 0.05) the branch is shed with all its sub-branches. The trunk is never shed.
6. Branch girth with the pipe model: tip metamers have a small diameter, and at every branching point d^n = d1^n + d2^n (n = 2.5). Width never shrinks when branches are shed, so remember the diameter of shed branches. Draw tapered brown branches from these diameters.
7. Simple foliage: green leaves on the young metamers, a ground plane and a sky, and a small HUD with season, metamers, shed, lambda and seed.
8. The tree grows from season 1 to a target of 30. Opened with no parameters the page starts at once with seed 1 and lambda 0.5, grows about one season per second while the camera slowly orbits, and stops growing at season 30. Drag with the mouse to orbit, wheel to zoom; O toggles the slow automatic orbit, Space pauses or resumes growth, N grows one season, R restarts from the seed.
9. Required test hooks, used by an automatic checker, they must work exactly like this:
- URL parameters: ?seed=<integer>&lambda=<0..1>&seasons=<target, default 30>&phyl=spiral|alternate&autoplay=0|1 (default 1)&orbit=0|1 (default 1)&instant=1. The same seed and lambda must always give the same tree (seeded random generator, never Math.random in the simulation). instant=1 simulates all seasons at load, before any animation, then shows the finished tree. autoplay=0 starts paused at season 1; growth then only happens through N or setSeason.
- window.setSeason(n) grows the tree to season n (restarting from the seed if n is below the current season) and redraws.
- window.treeStats() returns a plain object at any time with numeric season, metamers, buds, height, crownWidth, shed and a boolean done (true once season has reached the target). metamers = live metamers (after shedding); buds = live buds, terminal and lateral; height = highest metamer end point, the seedling base at y = 0, y up, in internode units; crownWidth = the larger of the x extent and the z extent of all live metamer end points; shed = cumulative number of metamers removed by shedding.
- ?instant=1 with the defaults must finish all 30 seasons in well under 60 seconds in headless Chromium (a few thousand to a few tens of thousands of metamers): typed arrays for the grid, and rebuild the drawn geometry only when the tree changed.
10. Use WebGL (three.js from a public CDN script tag is fine, or plain WebGL) and keep everything in a single HTML file I can open in Chrome, no build step. It must run smoothly with no console errors.
