# voxel series: hardening log + run protocol

operator ask (2026-10-22, GPU thread): "let's make sure we take notes of all of this so we actually harden this process by all our tests".
this file is the distilled rulebook. the dated narrative stays in `../long-task-voxel-status.md`; per-model parameters live in `model-params.md`; the skill copy is `capsule-rig-ops/references/voxelbench-agentic.md`. every new finding gets a row here IN THE SAME TURN: symptom, run that showed it, fix, where it is enforced, how it was tested. a lesson with no enforcement point is marked OPEN.

## run protocol (every voxel run, release-day or queued)

1. parameters first: `scripts/card-params.py <hf repo> --gguf <file>`, one row in `model-params.md` (sampling, output/reasoning budget, effort knob, template notes, card url + fetch date). pass `PARAMS_SRC`, `SAMPLING_FLAGS`, `RB`.
2. the model loads on llama.cpp first (day0-fastlane); never Ollama or another wrapper as a stand-in.
3. `DRYRUN=1` green before the real run (day0-voxel.sh or the queue item). red paths are part of any script change.
4. timing: long work in heures creuses (01:10-06:10, 14:10-17:10 CEST); exception: one reactive release-day voxel run per release at any hour; an operator "now" is his call.
5. watcher on (cron `42a7e673a270` + `/opt/data/scripts/voxel-state.py`, slug list updated), deliver to the GPU thread, readout cron armed for the expected end.
6. after the run: gate verdict, metrics, sceptical 8-element vision read against the Qwen reference, orbit clip with a calibrated turn, vault entry + this file.
7. post rules: a gate FAIL (broken page) is one line in the board; a gate PASS is a bench result and is shown, weak ones included, as a side-by-side attributed to the model (same prompt, hour, harness, card), "first look" framing, never a ranking, quant + ctx + RTX 5090 on screen, offload flagged, settings source citable.

## lessons (symptom -> fix -> enforced where -> tested)

### model behaviour inside the harness
- L1 runaway thinking. pilot 66v spent a 79k-token thinking block (71% of ctx) before the first tool call; Hermes compaction then dropped the plan (93.3K -> 31.8K). fix: `--reasoning-budget 16384` + budget message ("Stop planning and write the files now..."). enforced: day0-voxel.sh `RB` (default 16384, card budget wins, e.g. Flint 32768) and every queue item; preflight asserts the flag exists in the build. tested: 66w/66x ran capped.
- L2 retyped output path. MSM v1 (66w) wrote to a misspelled sibling dir `qwen38-27b-q6kmsm1/work`; official gate saw no html (hand gate PASS). fix: the exact absolute output path is appended to every run prompt ("copy this path, never retype it") + a path-miss fallback that grades the fresh stray html and flags it in `path-miss.json`. enforced: day0-voxel.sh + queue items. tested: v2 landed on the exact path.
- L3 self-reported "done" is not a verdict. smoke2 and Muse 66y were judged done on blank pages (66y: a regex merge of 6 subagent modules left `);` behind -> `Unexpected token ')'` -> no canvas, judged done in 7.6 min after `head`/`ls`/grep "verification"). fix: Hermes `/goal` quality gate running our gate.py at every turn boundary (docs: hermes-agent.nousresearch.com/docs/user-guide/features/goals#quality-gates). enforced: run_agent.sh `GATE_CMD`; day0-voxel.sh sets it by default (`QGATE=0` off). tested: CPU tiny-model probe x2 + Muse 66zz (one red gate at turn 1, then PASS, 21 min).
- L4 gate ordering trap. the CLI judges right after each turn and a queued slash command does not defer it, so `/goal gate add` typed after `/goal` lands after turn 1's verdict. fix: warm-up message keeps the loop busy, `/goal` + `/goal gate add` queue behind it; the driver checks the pane order (Goal set < Gate added < first kickoff) and writes `gate-registration.json` when late/missing. enforced: run_agent.sh. tested: probe + 66zz ("registered before the first goal turn (pane lines: goal 78, gate 97, kickoff 102)"). FAILED once at 19:03 CEST: a fast model (warm prompt cache) finished the warm-up in < 2 s, /goal ran idle and its one-turn "done" came before the gate ("/goal gate add: no active goal"; the driver flagged gate_missing). fix: the driver SIGSTOPs the idle model server (pid from `ss -ltnp` on the port) while it types the warm-up, /goal and /goal gate add, then SIGCONTs it (~5 s, trap guarantees the CONT), so both lines always queue behind a hanging warm-up. tested: 3 of 3 tiny-model probes 19:06-19:08 CEST registered before turn 1, server back to running state.

### parameters and fairness
- L5 wrong sampling. ### harness and capsule environment
- L8 headless Chromium on capsule needs `libasound.so.2` (in `~/voxelbench/lib`), `--no-sandbox` (AppArmor userns), `--use-angle=gl-egl` (Vulkan loses the context); playwright's ffmpeg is vp8-only, x264 via `~/voxelbench/ffmpeg` with `-nostdin` (SIGTTIN under tmux). enforced: gate.py / orbit scripts; day0 preflight checks the paths.
- L9 Chromium inside the model's Hermes terminal failed to launch (TargetClosedError, 66zz 17:52) while the Hermes gate subprocess and plain ssh launched fine. ROOT CAUSE (19:00 CEST, reproduced without a model by calling Hermes' terminal_tool directly): Hermes points TMPDIR at `<profile>/cache/scratch` for terminal commands (`hermes_constants.apply_scratch_tmp_env`); our bench profile names make that path 76 chars and Chromium's AF_UNIX socket under TMPDIR passes the 108-byte limit (TMPDIR of 40/60 chars launch, 70/80 fail). Hermes already guards its own browser tool with `socket_safe_tmpdir()`, not terminal commands. fix: `apply_scratch_tmp_env` respects a TMPDIR the user set, so run_agent.sh `VX_TMPFIX=1` starts Hermes with `TMPDIR=/tmp/vxt-<md5 8>` (verified in the Hermes process environ; gate.py through terminal_tool rc 0 with it, rc 2 without). default 0 so the queued one-variable reruns (66z, 66zy) keep the old harness like every earlier run; day0-voxel.sh and new items set 1; new baseline 66zz1 (Qwen msm-v2, h2 harness). likely also behind Qwen v1's "headless tab keeps vanishing". upstream: github draft candidate (deep profile homes break Chromium/AF_UNIX tools in terminal), gated.
